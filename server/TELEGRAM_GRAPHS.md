# Графики в Telegram

Кнопка **«📈 График за 6 часов»**, команды `/graph` и `/chart` отправляют PNG
за последние шесть часов на момент запроса. Доступ — только у активных участников
в личном чате. Интервал между запросами — 30 секунд. Новый замер на часах
этот запрос не запускает.

Автоматические графики приходят в **08:00 и 20:00** в часовом поясе
`TELEGRAM_TIMEZONE` (по умолчанию `Europe/Minsk`). Утренний период — с 20:00
предыдущего дня до 08:00, вечерний — с 08:00 до 20:00. Конечная граница не
включается: замер на ней относится к следующему периоду.

Получатели автоматических отчётов — активные участники, которым разрешены и
включены уведомления. Право просмотра без уведомлений позволяет запросить
график вручную. Перед отправкой бот повторно проверяет доступ и настройки.
`TELEGRAM_CHARTS_ENABLED=false` отключает автоматические графики; ручные
запросы продолжают работать.

При первом запуске нового функционала бот запоминает текущий интервал и
ждёт следующей границы. После последующих перерывов он отправляет только
последний завершённый период, отменяя более старые ожидающие графики.
Маркер расписания и очередь хранятся в SQLite и переживают перезапуск.
Telegram API не гарантирует отсутствие дубля при потере ответа на уже
доставленное сообщение; повторная постановка одного интервала защищена
уникальным ключом очереди.

Данные графика отбираются тем же сервисом, что и в веб-интерфейсе. Время точки —
время измерения. Повторные копии показания, в том числе внутри heartbeat,
не увеличивают число точек. Пауза более десяти минут разрывает линию и
выделяется серым. Это отсутствие замеров, а не подтверждение потери связи.
Среднее относится к полученным значениям, не ко всему времени периода.
Текущие пороги не рисуются поверх истории: история изменения порогов недоступна.
ИИ не вызывается.

## Обновление

Образ Docker содержит GD/FreeType и DejaVu Sans. Пересобрать нужно оба сервиса:

```powershell
docker compose --profile telegram build api telegram
powershell -NoProfile -ExecutionPolicy Bypass -File .\Test-Server.ps1
docker compose --profile telegram up -d api telegram
```

API выполняет новую миграцию при запуске. Проверка `Test-Server.ps1` использует
отдельную SQLite `:memory:` и не очищает рабочую историю.

## Проверка без ожидания расписания

1. Напишите боту `/graph`. Ожидается PNG за последние шесть часов с краткой
   статистикой. В вебе выберите тот же период; время окончания запросов может
   немного различаться, поэтому число точек не обязательно будет одинаковым.
2. Локальный PNG без отправки и без изменения очереди или расписания:

```powershell
docker compose exec api php artisan telegram:graph-preview --hours=6
```

Откройте `server\data\telegram-chart-preview.png` на компьютере.

3. Предпросмотр утреннего запланированного периода с фиксированной датой:

```powershell
docker compose exec api php artisan telegram:graph-preview --scheduled --at=2026-10-09T08:00:00+03:00
```

Это период 08.10 20:00 — 09.10 08:00. Команда только читает историю и сохраняет
картинку. Время теста не меняет реальные часы сервера или расписание бота.

Автотесты проверяют две границы расписания с замороженным временем, повторный
tick, восстановление после простоя, права получателей, повторную доставку
после 429, реальный multipart PNG, дедупликацию и отсутствие линии через паузу.
В вебе добавлен период «Последние 12 часов».
